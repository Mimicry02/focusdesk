2 / Siapkan Supabase dan admin pertama

  1. Buat project Supabase. Gunakan project khusus Focusdesk bila memungkinkan. Catat password database di tempat aman; aplikasi ini tidak memerlukan password database di HTML.
  2. Buka SQL Editor → New query. Salin seluruh isi supabase/01_schema.sql, lalu Run. Script menggunakan tabel berawalan fd_ dan tidak menghapus tabel aplikasi lain.
  3. Buka Authentication → Users → Add user. Pilih membuat akun, isi email Anda dan password pribadi. Pastikan email akun terkonfirmasi/Auto Confirm. Jangan mengandalkan signup publik untuk membuat admin.
  4. Buka supabase/02_bootstrap_admin.sql menggunakan text editor. Ganti GANTI_DENGAN_EMAIL_ANDA@gmail.com dengan email yang sama persis seperti akun tadi.
  5. Jalankan script bootstrap di SQL Editor. Sekarang akun Anda memiliki role=admin dan is_active=true.
  6. Di pengaturan Supabase Auth, matikan Allow new users to sign up untuk penggunaan berbasis undangan. Biarkan provider Email aktif. Akun yang dibuat di luar alur aplikasi tetap inactive secara default sebagai lapisan pembatas tambahan.

Bootstrap hanya untuk admin pertama. Setelah ada admin aktif lain, script menolak penggunaan ulang untuk email berbeda. Buat admin berikutnya melalui User management setelah login.

3 / Deploy ke Vercel

Opsi A — Upload proyek dengan Vercel Drop

  1. Buka vercel.com/drop dan login.
  2. Unggah ZIP proyek atau folder yang sudah diekstrak. Pastikan root berisi package.json dan vercel.json, bukan folder tambahan yang salah.
  3. Gunakan konfigurasi build dari paket: Framework Preset: Other, Build Command: npm run build, Output Directory: dist, Node.js: 22.x.
  4. Setelah URL tersedia, catat origin production yang akan dipakai login, misalnya https://focusdesk-justin.vercel.app. Lanjutkan environment variables di bawah, lalu redeploy.

Vercel mendokumentasikan unggah file/folder/ZIP dan deployment melalui Git/CLI. Paket ini belum dijalankan pada akun Vercel Anda. Jika alur upload tidak memproses folder API/build, gunakan impor Git atau CLI di bawah.

Opsi B — Ekstrak ZIP dan impor Git

  1. Ekstrak ZIP. Masukkan seluruh isi proyek ke repository GitHub pribadi. Jangan upload file .env berisi key; .env.example aman karena placeholder.
  2. Di Vercel pilih Add New → Project → Import Git Repository.
  3. Pilih root yang memiliki package.json. Pakai pengaturan build di atas dan isi environment variables.
  4. Deploy. Setelah URL final diketahui, koreksi APP_URL lalu redeploy bila diperlukan.

Opsi CLI

Dari folder proyek setelah ekstrak, Anda dapat menjalankan npx vercel untuk menghubungkan proyek lalu npx vercel --prod untuk production. Atur environment melalui dashboard Vercel. CLI memerlukan Node.js dan login Vercel.

Empat environment variables wajib

Vercel → Project → Settings → Environment Variables. Isi untuk environment Production; setelah berubah, lakukan redeploy.

SUPABASE_URLhttps://PROJECT_ID.supabase.coProject URL Supabase. Tidak memakai /rest/v1/ di belakang.
SUPABASE_PUBLISHABLE_KEYsb_publishable_...Supabase Settings → API Keys. Legacy anon key juga didukung.
SUPABASE_SECRET_KEYsb_secret_...Hanya server Vercel. Legacy service_role key juga didukung. Jangan masukkan ke HTML/JavaScript public.

Tidak perlu mengedit JS untuk memasukkan key. Browser berbicara ke API Vercel; sesi berada di cookie HttpOnly. Key rahasia tetap di environment server.

Gunakan URL production yang sama dengan APP_URL saat login. URL preview/domain alternatif akan ditolak untuk operasi tulis sampai konfigurasi origin disesuaikan. Bila mengganti custom domain, ubah APP_URL, URL Supabase Auth, dan redeploy bersama-sama.

4 / Redirect Auth dan SMTP

  1. Buka Supabase Authentication → URL Configuration.
  2. Set Site URL sama dengan APP_URL.
  3. Tambahkan Redirect URLs yang tepat:
https://NAMA_APLIKASI.vercel.app/?flow=invite
https://NAMA_APLIKASI.vercel.app/?flow=recovery
  1. Gunakan template Invite dan Reset Password default dengan link konfirmasi Supabase. Jangan mengganti menjadi flow PKCE/custom token_hash; paket ini memproses token fragment dari link default.
  2. Konfigurasikan Custom SMTP pada Supabase Auth sebelum mengundang email pengguna lain. Gunakan detail host, port, username, password, dan From dari penyedia email Anda.
  3. Simpan, lalu uji Forgot password pada akun Anda. Buka link di email, buat password baru, dan login.
SMTP bawaan Supabase bukan layanan email produksi. Dokumentasi menyatakan pengiriman bawaan dibatasi ke alamat yang terotorisasi pada tim proyek dan memiliki batas pengiriman rendah. Jika invite/reset gagal karena rate limit atau alamat tidak terotorisasi, konfigurasi Custom SMTP—jangan menonaktifkan verifikasi email sebagai jalan pintas.

SMTP Auth dipakai untuk invite dan reset password. Daily briefing di bagian berikutnya memakai Resend API secara terpisah. Memasang salah satunya tidak otomatis memasang yang lain.

5 / User management

Data tugas tetap pribadi. Admin aplikasi dapat mengelola akun, tetapi tidak membaca tugas akun lain. Pemilik infrastruktur Supabase yang memiliki SQL/service key tetap berbeda dari admin aplikasi dan mempunyai kewenangan database.

Akun sendiri tidak dapat dinonaktifkan atau diturunkan rolenya melalui aplikasi. Tidak ada hard delete pengguna agar data tidak hilang tanpa sengaja. Akun inactive yang sudah melihat data sebelumnya tidak dapat dipaksa “melupakan” informasi yang telah dibaca.

6 / Aktifkan daily briefing (opsional)

  1. Siapkan akun Resend dan domain pengirim terverifikasi. Ambil API key.
  2. Tambahkan environment berikut ke Vercel Production:
NameValue
RESEND_API_KEYAPI key dari Resend.
EMAIL_FROMFocusdesk <notifications@domain-terverifikasi-anda.com>
CRON_SECRETString acak minimal 32 karakter. Simpan hanya di environment server.

Contoh membuat nilai acak di Node.js, lalu salin hasilnya ke environment:

node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
  1. Redeploy. File vercel.json menjadwalkan /api/digest pada 0 1 * * * UTC, target 08.00 WIB.
  2. Di aplikasi, buka Settings → aktifkan daily email briefing → Save preferences.
  3. Klik Send today’s briefing untuk uji kirim manual. Penerima adalah email akun Anda yang terverifikasi. Periksa inbox, spam, dan log provider.
  4. Periksa status accepted/failed di Settings dan invokasi cron di Vercel.

Vercel Hobby memakai jendela waktu per jam; jadwal 08.00 WIB bisa berjalan antara 08.00–08.59 WIB. Versi ini tidak menawarkan jam kirim per pengguna. Ada satu briefing per tanggal WIB, sehingga kirim manual akan membuat cron pada hari yang sama melewati akun itu.

Status accepted berarti permintaan diterima penyedia email, bukan jaminan masuk inbox. Tidak ada delivery webhook, worker antrean, atau retry otomatis pada versi ini. Jumlah penerima cron dibatasi 10 akun aktif opted-in; perlu pengembangan antrean untuk skala lebih besar. Jika tidak menggunakan email sama sekali, Anda boleh menghapus bagian crons dari vercel.json dan redeploy.

Membuat tugas

  1. New task → nama hasil pekerjaan, kategori, project, jenis, prioritas, dan status.
  2. Deadline adalah batas selesai. Scheduled day + Start time adalah waktu pengerjaan. Misalnya deadline Jumat, tetapi pengerjaan Rabu 09.00 selama 90 menit.
  3. Isi estimasi durasi dan notes, lalu centang Top 3 jika prioritas utama hari itu.
  4. Save task. Centang daftar tugas ketika selesai. Untuk edit, klik nama tugas.
  5. Untuk backlog tanpa jadwal: pilih Backlog dan kosongkan tanggal/jam pengerjaan. Status Backlog saja tidak menghapus tanggal.

Jika muncul pesan konflik versi, data telah berubah dari tab/perangkat lain. Muat ulang lalu edit ulang agar tidak menimpa perubahan terbaru. Delete memakai konfirmasi dan tidak memiliki undo.

Calendar dan timer

Export calendar menghasilkan .ics semua tugas terjadwal yang belum selesai. Add to Google Calendar membuka draf event dari data tersimpan saat detail dibuka. Simpan perubahan lalu buka kembali detail sebelum menggunakan tautan. Kedua cara ini manual; perubahan/penghapusan tidak tersinkron otomatis. Tugas tanpa jam diekspor pada 09.00 WIB.

Timer 25 menit memiliki Start/Pause/Reset, tidak otomatis menyelesaikan tugas, tidak menyimpan histori jam, dan hilang saat reload/logout.

Batas fitur

Belum termasuk public signup UI, subtasks, dependency, lampiran, tugas berulang, custom category, project master, shared team tasks, MFA UI, hard delete user, migrasi data contoh lama, dan Google Calendar sync otomatis.

8 / Troubleshooting

GejalaPeriksa
Konfigurasi server belum lengkapEmpat environment wajib, scope Production, nilai Project URL, dan redeploy setelah perubahan.
API tidak tersedia / respons HTMLRoot proyek benar? Folder api/server ikut? Jangan deploy hanya public/dist. Gunakan Git/CLI jika upload diperlakukan sebagai static-only.
Origin tidak diizinkanAlamat browser harus sama dengan APP_URL. URL preview atau domain lain tidak otomatis diizinkan.
Akun belum aktifAdmin pertama: bootstrap SQL dengan email yang benar. User lain: Manage → Active oleh admin.
Invalid login credentialsPassword dan email, akun Auth sudah dibuat, email terkonfirmasi, serta project URL/key mengarah ke project yang sama.
Email address not authorized / email rate limit exceededKonfigurasi SMTP Supabase dan rate limit provider. Tunggu sesuai batas; jangan kirim berulang-ulang.
Tautan reset/invite kedaluwarsaMinta link baru. Periksa Redirect URLs dan template link default Supabase. Link lama/sudah dipakai tidak dapat diandalkan.
Undangan diproses tetapi aktivasi gagalRefresh User management lalu aktifkan akun yang sudah muncul. Jangan langsung mengirim ulang undangan.
Briefing tidak terkirimResend API key, verified domain, EMAIL_FROM, CRON_SECRET, opt-in user, confirmed email, serta Vercel cron/function logs.
Briefing skippedSudah diproses hari ini atau klaim sedang berjalan. Periksa provider/log sebelum mencoba lagi.
Tugas tidak tersimpan / conflictPeriksa status aktif akun, validasi tanggal/durasi/Top 3, dan versi tugas dari tab lain. Muat ulang data.

9 / Verifikasi dan langkah setelah deploy

12 unit/API tests passed SQL/RLS tests passed Static build passed

Paket diuji dengan mock API dan PostgreSQL lokal berbasis PGlite untuk SQL/RLS. Login Supabase hosted, cookie domain Vercel, undangan SMTP, pengiriman Resend, cron production, serta browser end-to-end belum diuji dengan akun Anda.

  1. Login admin, buat satu tugas, refresh: data harus tetap ada.
  2. Invite user kedua dan login di browser/session terpisah: tugas admin tidak boleh terlihat.
  3. Buat tugas kedua: admin tidak boleh melihat tugas user tersebut.
  4. Nonaktifkan user kedua: request data berikutnya harus ditolak. Aktifkan lagi: data tetap ada.
  5. Uji password reset setelah SMTP siap. Uji briefing sekali lalu ulangi; permintaan hari sama harus skipped.

Panduan teknis lebih rinci ada di docs/ARCHITECTURE.md, panduan penggunaan lengkap di docs/USER_GUIDE.md, dan catatan batas pengujian di docs/TEST_RESULTS.md.
